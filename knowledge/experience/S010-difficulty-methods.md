# S010｜业务机制增难与真实答卷驱动的最小迭代

## 来源与证据边界

依据一份第三方增难方法文本的结构化阅读与评审笔记整理。原材料含十节及一个编号不连续的小节；没有补造缺失小节，也没有对应的完整运行案例。它与 [S006](S006-task-experience-notes.md) 中的截图高度相近，但作者、原始文件和版本关系未证实，不能重复计为独立验证。

## 增难前提

围绕有负责人、用途和后果的业务决定设计。公开输入必须充分，参考可独立推导，评分按事前冻结的责任验收。专业难度、必要工作量与运行长度分别判断；允许正常脚本和批处理，不以堆量、拆调用、等待、不可读文件或删除规则制造困难。

## 可研究的八类机制

| 机制 | 需要作答者建立的关系 | 教师侧应核对的错法与正常对照 |
| --- | --- | --- |
| 证据效力 | 时间、授权、适用对象和撤销共同决定某份信息能否用于当前工作 | 只取最新、把草稿当正式结论或以摘要代替依据；同时保留有效正常版本 |
| 对象与口径 | 识别真正业务事项、计量基数、总额与增量、账面与实际状态 | 重复确认、漏增量、重复抵扣或分母错；核对象和单位而不只看合计 |
| 状态与时序 | 来源和时点决定当前状态及后续合法动作 | 旧状态覆盖现状、取消项重新进入、摘要与明细不同步；核顺序是否有公开依据 |
| 约束组合 | 目标、硬条件、可调整项、资源、优先级和例外共同作用 | 只看收益、遇一项不满足便停止，或倒改假设凑阈值；保留合法调整路径 |
| 情景与方案 | 选择成立条件、风险、备用或整改及交付对象 | 方案标签多但没有实际取舍；正确拒绝、延期或保守方案也应被允许 |
| 跨材料与成果一致 | 用业务键、时间和版本关联规则、明细、审批、流水和最终指令 | 字段错位、旧公式、汇总与明细冲突或执行文件漏更新；核真实依赖 |
| 真实干扰和正常值 | 意见、摘要、旧版或异常线索有合理成因，正确依据仍充分 | 不将所有醒目线索固定设为错，也不把正常空值当异常 |
| 真实答卷迁移 | 从实际处理和产物发现局部正确、整体交付失败等机制 | 区分已观察错误与原因假设，不靠换名、日期或格式复用失败结论 |

只选自然共存且改变业务结果的关系，不要求每题集齐全部类型。

## 私有设计记录

从最终决定反推使用者、可得信息、判断关系、交付证据、错误后果及评分依据。对每个主要难点记录公开位置、业务依据、正确结果范围、顺手错法、可见产物、下游影响、根因关系和正常对照。

教师可保存这些分析，但不能把本案判断顺序、错误清单、目标分数或推荐结果写入公开输入。公开条件与正常上游成果照常提供；它们已承担的工作须从独立能力声明中扣除。

## 评分、读卷和下一轮

每项评分对应一个可区分、可观察的业务责任。封闭结果注明对象、单位、期间、精度和容差；开放结果明确硬约束和合理替代。一个根因可能有多个后果，应记录依赖，不能把同一结果换名重复处罚，也不能仅凭同一根因豁免全部独立责任。

先核测试有效性，再读全卷并记录：已覆盖且命中、已覆盖但漏评、未覆盖新错、正确反例、环境问题。可见引用、计算、工具和文件支持的处理才记作观察，原因解释还需反证。

按业务重要性、覆盖缺口和修复收益决定保留、补评分、修题、改参考、记录环境或不再迭代。先修歧义、不可解和评分错误；同步受影响文件并形成新版，旧输入、原卷和原评保留。已经识别的稳定错误不无限叠加，下一投入也要纳入模型主要成功的方法，而非只追失去的小分。

## 必须限定的来源措辞

- 来源提出固定数量的因素建议；可借其检查依赖，不把数量变成考点硬门槛。多条件推导与单一验收责任可以并存。
- “替换轻易得分”只能用于恢复真实且未覆盖的责任，不能因模型答对便删除基础项、临时加权或追加条件。
- 关于旧卷的争议应区别同标准纠错和按新标准探索：保留原评，分别记录来源和版本，不冒充新运行。
- 新关系、更多附件或一次教师试解，不自动证明值得正式投测。模型稳定成功时可以结束当前候选、保留资产并研究新的完整责任，不为制造失败强行扩包。

方法没有效果保证；真实投入、模型与平台参数仍按[本批确认](../policy-notes/README.md)。
