# S011｜第三方 skill 评审：岗位知情边界与语义保真

## 来源与适用范围

依据一份第三方出题 skill 粘贴文本的阅读评审整理。原文本引用了多份未完整提供的脚本、其他 skill 和本机工具约定，部分句子不完整；没有安装包、实际题包或完整运行链，因此可评价方法，不能宣称执行功能或效果已经验证。

原文中的个人用户偏好、历史期次、AI 许可和默认双模型安排，不属于本仓库所有使用者的现行授权。其与其他经验的作者和版本关系也未确立。

## 值得吸收的方法

| 审查面 | 具体做法 |
| --- | --- |
| 岗位研究 | 研究实际成果负责人、高发差错、真实机制和适用规则，形成合理错法、反证、允许结果与行动影响 |
| 独立核验 | 从公开输入建立答案与正常对照；多个文件若都复制同一答案键，不算独立证明 |
| 材料知情边界 | 核每份材料由谁、为谁、为何、何时形成，处于哪个流程位置；作者不能借业务记录预知未来回执或越权裁决 |
| 未知状态 | 未返回、空值、未取得不自动等于未发生、失败或已否定；档案编号也不能代替必要原件 |
| 自然表达 | 业务交办与制度可保留，但给解题教程换邮件外观仍是预填；相似结构只是复核线索，不是生成概率证据 |
| 要求归属 | 区分出题方制作要求与作答方交付责任，不能把本机软件或署名偏好变成隐藏评分禁令 |
| 语义保真 | 润色保留金额、单位、时区、对象 ID、状态、否定、权限和效力；新增事实条件属于改题，需升版本并核验 |
| 返修复审 | 先找全同类问题、按文件集中改，再通读全部公开输入，检查是否新增了解题提示或跨文件冲突 |

## 评分与迭代

以终稿实际结果验收，正确描述条件或公式不能替代正确交付。对原标准已准确识别的错误，可以保存证据而不再增项；只有漏检、判据不清或业务责任未覆盖才修评分，并另存版本。

根因诊断与成果计分分别记录。不要将同一输出错误重复扣分，也不要只因根因相同而忽略预先定义的独立交付责任。合理替代方案、正常对照和已经纠正的终稿都应得到承认。

## 执行依赖与 Python 边界

借用外部 skill 时，核真正取得的文件、脚本、权限和版本；“文中提到某工具”不等于已安装、已调用或已完成审查。把有价值做法映射到现有入口，不额外复制一套总控、经验库或向量库。

Python 可检查角色、来源和时间字段，核清单、引用、摘要、差异与核算，并保存实际结果；不能仅凭字段齐全或关键词命中，判定岗位越权、材料泄题、空值含义或业务价值。语义结论仍需回到规则、原件和业务后果。

来源中的固定制件软件、历史字段、默认模型对比次数和数量偏好不直接采用。格式检查、样稿、真实运行和平台审核分别报告；缺少完整运行证据时，不给出难度或通过率结论。
