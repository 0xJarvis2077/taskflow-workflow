# 历史规则快照如何使用

公开知识库保留规则阅读和核实的方法，不发布私人项目授权、题目资料或完整第三方说明。历史会议、转存文本、经验分享和本地建议是不同层级，不能合并成一套永远有效的“平台规则”。

## 新批次先建立自己的有效快照

1. **确认对象与版本。** 写清项目、批次、行业和交付范围；取得规则的发布主体、发布日期、生效时间、版本或可核通知。文件名有“新版”或序号不等于更新。
2. **确认实际义务。** 核题目类型、行业／岗位字段含义、原创与去重、来源和构造材料范围、AI 参与许可、脱敏及保密责任。某个历史用户的许可只覆盖其明确授权，不能迁给其他人。
3. **确认运行与验收。** 分别核目标模型、工具、权限、正常交互、总分、评分形式、执行计数、完成状态、时间扣除、预算与上限。新批次各角色模型未明确选择时，按[协作架构](../../docs/task-collaboration-architecture.md)先问清，不能从旧材料代填。
4. **确认操作与交付。** 核附件格式、大小、填表字段、领取／保存／提交／返修权限及截止。文字流程与真实界面回执分别记录，不把“保存成功”当作审核通过。
5. **登记冲突与未决。** 同一事项若有不同口述、图片等号或截止时点，保存各自范围与依据，定向核实影响当前动作的缺口。没有依据时保持未知，不选择最方便的一条。
6. **冻结适用范围。** 将已确认要求及证据版本绑定本批；规则改变后另存快照和影响分析。已经运行的旧卷按其原标准留存，不能用新规则倒改原成绩。

## 常见误用

| 历史材料中的内容 | 正确使用方式 |
| --- | --- |
| 题数、行业额度、领取超时、返修次数、截止、奖励或报销 | 作为当时运营安排；本批重新确认，不据此操作或承诺收益 |
| 分数、轮数或时长阈值 | 先核适用版本及完整逻辑，尤其“且／或”、等号、完成前提和有效计数 |
| 推荐模型、工具能力、第三方入口或型号自报 | 分开记录请求值、本地可证配置与实际服务未知项，不默认等价或授权外传 |
| “真实”“脱敏”“构造”“仿真”和 AI 制作 | 分别核事实来源、变换方法、业务可解性和许可，不靠声明证明真实，也不伪造来源 |
| 个人规定的附件数、体积、因素数、相似率或固定软件 | 可作检查启发，不能未经证实升为平台门槛或施加给作答者 |
| 自述低分、前置通过或完成制作 | 与正式验难、最终收录和结算分开；缺少完整证据就不升级状态 |

## 现有公开来源能说明什么

- [S001](../experience/S001-phase07-meeting.md) 与 [S014](../experience/S014-phase07-task-document.md) 是历史项目说明类笔记，可研究规则结构；发布链、缺失附件及日期／权限差异仍有限制。
- [S002](../experience/S002-selftest-guide.md) 与 [S003](../experience/S003-selftest-meeting.md) 提供自测操作及计量讨论；严格版本关系、正式配置与计数实现并不完整。
- [S005](../experience/S005-beginner-meeting.md) 明确涉及另一个历史期次，尤其要防止字段与编辑权限跨期套用。
- [S006](../experience/S006-task-experience-notes.md)、[S007](../experience/S007-task-experience-meeting.md) 及其他[经验笔记](../experience/index.md)提供个人实践和方法，不替需求方发布规则，也不提供方法必然有效的证据。

## 缺证时如何继续

先区分影响当前动作的关键条件与可以独立研究的部分。涉及模型选择、外部传输、真实调用、提交或不可逆动作的必要条件未明确时，补问并保留待办；仍可开展不依赖该答案的资料整理和方法研究。不要把未决项删掉，不扩成必须先证明所有平台内部实现的停工门槛。

后续规则若获得可信更新，保存原文定位、确认范围和变更理由，再调整当前批次配置。不要因为改了知识库、模板或程序字段，就声称平台能力、隔离、业务质量或题目难度已经通过验证。
