# 出题与本质质检

公开方法。来源线索主要为 S001–S005，补充 S008、S010–S016；编号的材料类型、历史范围和采用限制见[经验来源索引](../experience/index.md)。以下方法检查任务在业务、证据和评判上是否成立，不代表任何平台的固定实现，也不宣称已证明能使题目达到指定难度。

## 从真实任务形成题目

先从业务需求和领域资料确认谁使用结果、需要作出什么决定、有哪些真实机制与约束、专业人员为何费时及错误后果。题设记录与数据可在本批明确允许的制作范围内设计，不要求用户先提供整套私人原件；引用事实、原件处理与设计假设分别留在内部证据中。不虚称设计记录为已发生业务，也不编造职业经历或外部出处。AI 制作是否允许及具体范围应在本批核实，不能从本方法或历史项目继承许可。

把任务拆成一条有因果关系的完成路径：每步使用哪些材料，产出什么中间结论，下一步为什么依赖它。复杂性可来自多源对账、口径转换、矛盾证据核验、约束取舍、专业判断及结论落到可用交付物。仅增加页数、重复操作或无关子任务，不构成有价值的难度。

取得本批角色模型和工作范围确认后，可以从行业分类启动岗位研究，不必等待完整附件齐备。按最终成果的实际负责人选择岗位；已有角色或分类约束时遵守该约束。研究落到岗位高发差错、公开案例和适用规则，在内部记录“错法为何看似合理—可取得的反证—正确或允许结果—改变什么行动”，并设置正常对照。不能用泛泛的“模型容易幻觉”代替领域研究；外部案例与题设改编分别留据。[S008步骤1–2；S011 L8、L18–20]

资料搜集可按需要分工，成本较低的模型只是可选方式，不设固定模型编制。搜集者交付原始出处、日期/版本、具体定位、与业务问题的关系及尚缺证据；主审回读承载关键判断的原文，确认权限、时点、适用范围和实际后果能否支撑题目。有缺口再定向补充，不将搜索摘要、资料数量或另一模型的肯定当作事实核验。是否分工及模型选择仍按资料类型、可核验性、已有服务/数据授权和成本确定。[S016第1、5条；与S007 E04/E19的主题关系不证明同源]

[S008步骤3](../experience/S008-ten-step-workflow.md)补充可操作的检查：对象、状态、权限、时间、资源、资金中与任务相关的条件，应共同改变同一个业务决定，而非各做一道小题。检查正常情形和合理路径是否仍成立，避免把所有记录都做成异常；不要求六类条件每题齐全。有据拒绝或延期也可能是合格交付；设计阶段可调整题设并同步核验，判答时不能为保留可行方案补入输入之外的事实。这是本地设计方法，不是新增题型门槛。

S005 提供一个获口头认可的结构例子：方案框架 → PRD → 基于 PRD 的测试用例 → 功能拆分、开发测试人员安排与排期。价值在于前后产物互相依赖；本地审查还要看测试是否覆盖需求、排期是否满足人员与依赖约束。缺少具体输入或可信业务约束时，不能只加几个文件名来声称任务复杂。这个例子未展示验难成绩。[S005 E18；覆盖与约束检查为本地方法]

题干明确输入、目标、使用对象、边界条件、允许工具和交付物验收要求。保留真实业务中需要判断的空间；不要把所有解题步骤写进题干泄露解法，也不要隐藏完成任务必需的信息。

确定任务载体时，先识别完成它必需的运行依赖，尤其是准备开发的专用服务、外部进程、状态存储、网络与文件权限。分别记录本地已验证的能力、目标交付环境已有依据的能力和未知项；不要求先证明平台所有能力。未知限制依赖它的交付声明和验证结论，其他研究与本地探索可继续。若目标是平台交付，将关键承载未知和可替代方案纳入[研发投入比较](difficulty-design.md)；有限原型可以用于补证，不因已标“未知”就默认投入完整专用环境开发。若改成交付静态文件，重新核验删去了哪些接续、执行或状态判断责任，并同步输入、标答和评分；原交互运行成绩不能直接迁移。

S004 的入门表达包含具体任务、背景或对象、要求、交付形式，可用于梳理已有需求；它是表达辅助，不能替代附件、参考和考点。创意、图片、代码或命题等通用能力示例，不自动覆盖正式收题范围，也不授予本批 AI 制作或外部操作许可。[S004 E03、E05、E08]

记录时分开专家本人行业/职业、任务业务领域/类型、题干赋予模型的角色。S005六期按本人身份填写职业；[S014 E03–E04](../experience/S014-phase07-task-document.md)七期副本明确L1职业按最终交付负责人、L2按实际执行岗位，并提供行业L1/L2列表。七期字段用途已补齐，完整职业分类树仍未取得；不能因字段同名沿用六期约束，正式枚举与来源版本另核。[S005 E13；S001 E03；Q19]

公开检索可以是任务的一部分，不必把所有公开文件机械地转成附件。按 S003，要明确检索对象与范围；政策等写名称，最好给网站和版本，英文材料也可。实际检查目标资料能否在允许工具下获取、版本是否唯一可识别；检索辨识本身是考点时保留合理检索过程，不把关键资料变成无法定位的谜题。带图 PDF、截图、流程图、PPT 是否可读应按实际文件核验。[S003 E14、E16；可访问性核验为本地操作]

S005 补充公开检索须明确范围、时间口径；文献优先提供全文，体量过大可用索引的口述需结合访问条件。索引不能代替无法获取的必要内容，提到校园网也不证明正式环境有订阅或登录权限。多文档可压缩；视频建议转文字/截图等，不用转换方式或格式名称代替可读性核验。[S005 E16、E27、E29]

历史来源对真实数据、仿真附件及材料制作的要求存在期次差异：S001 七期与 S005 六期的相关表述不能静默合并。新批次先核当前制作许可、引用及处理范围；真实事件引用、原件脱敏和题设设计分别留证，不将设计记录冒充真实业务。检查计算、日期、实体关系和约束一致；检测侧重点不能证明资料真实，制作许可也不替代事实核验。具体对外表达按[制作声明检查](#公开材料中的制作声明)处理。[S001 E04、E05、E10；S005 E21、E26]

S005 的历史脱敏口述强调先确定处理规则，再执行替换。实际处理时保留规则及一致性核验结果，检查跨文件同一实体、数值关系和任务可解性。原件处理、题设设计和对外上传是不同授权范围，不能从一种许可推断另一种许可。[S005 E25]

## 检查题目是否成立

| 检查面 | 要找的证据 | 典型失败 |
| --- | --- | --- |
| 价值 | 交付对象、使用场景、决策或行动后果 | 只是泛泛介绍行业，没有实际要完成的工作 |
| 可解性 | 关键资料和必要权限齐全，题干无互相冲突的硬约束 | 只有作者知道的隐藏事实；材料缺页；登录页面无法访问 |
| 复杂性 | 多步依赖、多源处理、专业判断确实必要 | 独立小问题拼盘；机械扩写；故意耗时 |
| 标答正确 | 每个关键结论有来源、计算过程或可辩护假设 | 标答用了未提供数据；公式、单位或时点错误 |
| 评分有效 | 考点对应任务要求，有可观察结果和失分依据 | 按作者措辞、排版偏好评分；合理替代方案被扣分 |
| 区分度 | 难点影响结果质量；业务核心比表面格式重要 | 分数主要由隐蔽格式陷阱或无关知识决定 |
| 独立与原创 | 与往期/同批题的目标、判断链、材料和交付差异 | 换公司名与数字复用相同问题；已收录题重投 |

专家不必只接受一个答案，但必须能验证候选答案是否正确、可用。若连专家也无法形成可靠参考结果或验收依据，应先解决这个缺口，不能把无法判分当成难度；尚不能判对错的任务不适合提交。[S003 E19]

涉及恢复、回滚或补偿的任务，沿拟采用及合理替代路线，核关键操作的成功与拒绝状态。仍需完成业务时，公开契约应支持后继合法动作，并接通角色权限、业务身份与历史保全、并发条件及所需工时；允许暂缓时核明适用范围和接续责任。用题目已有状态走查，不设置固定分支数或处理顺序。版本兼容与计算通过各证明相应范围，路线可执行性另留证据；制作期发现、独立质量结论及正式运行后的发现分别标记。

涉及异步增量、撤回或版本水位时，分别改变原件接收顺序与业务领取顺序，检查“高版已完成后低版才收到”和低版是否仍影响另一对象；不要用只覆盖全部已收原件的一种乱序测试代替晚到验证。资源最大版本、某成员已完成版本和来源历史完整性分别取证，不从最大值推造完整性保证。计划依赖原件集合时，再用一条相关低版新原件验证最大水位不变仍能拒绝旧计划或原子纳入；同时保留同对象旧操作不能撤销较新决定、正常无变化不抖动的相反控制。该检查适用于增量语义，不要求其他题增加无关分支或特定算法。

同案例派生不同文书须检查实质差异，不能只看交付物名称。S005 对这类重复题的回答残缺，暂不能形成统一接受或排除规则；保留具体题目、判断链和考点对照，必要时核实该期要求。[S005 E20；S001 E14、E26；Q20]

同一领域批量找方向时，按[批量选题与实质去重](topic-portfolio.md)先展开场景、任务、视角和服务对象，再检查每项的可判定考点。S009提供五种切口及文旅八方向，但标题/材料不同不能保证不重复；需比较核心决策、关键证据、推理与验收责任，并核每题独立成立。其“五期8题”不覆盖其他期次额度。

## 材料语义保真、贡献与输入边界

本节整理材料抽取、字段口径和岗位记录的语义检查。软件选择不构成业务质量证据；材料加工是否保真、是否替作答者完成判断、是否符合对外文档表达要求，需要分别核验。

| 加工对象 | 必查语义 | 不能据此直接判错 |
| --- | --- | --- |
| PDF/网页抽取 | 跨页、页码粘正文、表头/脚注归属和计量单位；关键结论回原页 | 只因文本排列不连续就认定原材料缺失 |
| 表格和口径 | 主体、期间、金额单位、分母、合并单元格、“同上”承接；工程量、点位数等不能混用 | 看到重复或空值就认定业务异常 |
| 编号和节选 | 业务原编号与抽取定位号分开；正文引用仍可追到实际附件；未取得部分单列 | 强制补齐原文跳号，或把节选当作完整原件 |
| 留白和模板 | 区分正常待填模板、实际未填记录、抽取漏失；公开空白模板有独立角色 | 将空白输出模板归为教师答案，或为了整齐删去它 |
| 脱敏和改编 | 同一实体跨文件映射一致，日期关系、单位、数值勾稽及证据效力保留 | 用改名、排版软件或删除制作标识证明来源真实性 |

每份材料检查作者、受众、形成原因、所处流程、形成时点及当时知情范围。归档人员可记录已收/未收，业务裁决须有相应职责与依据；角色不能预知未来回执。邮件、制度、日志和系统导出应符合各自用途，不能统一替接手者总结所有风险与正确结论。真实岗位交办可以保留，但给解题教程套上邮件头仍是泄漏；相似结构只能提示复核，相同系统的正常导出允许一致。[S011 L51、L53–54、L62]

“未返回、空值、未取得”不能直接改写成“未发生、失败、已否定”。例如认证字段为空，只说明当前记录未给出结果；是否可推断为未认证，仍取决于公开的字段定义、流程和证据。题设、标答与评分均保持证据原有的确定程度，不以作者设想补全未知状态。[S011 L56]

“所有成员均合法”“记录已完整”等全局保证，要核其来源、截止时点、适用主体和变更范围：它保证客户既有记录，还是也覆盖后续特定来源的写入？系统读回可以证明当前状态，却不能自动赋予模型自己的误操作业务授权，也不能让原保证追认新写入。真实、必要且有范围依据的明确规则应保留；不能为了增难删除它们，或以模糊措辞制造未知。

出题方的制作软件、署名或整理偏好不自动成为被测模型的限制或评分要求；必要的成果验收责任应有公开任务依据。润色前后核金额、单位、时区、ID、状态、否定、条件、权限、生效/撤销关系及跨文件引用；事实、文体、版面分别检查。纯措辞修订不能新增权限、付款日期或记录对应关系；实质改变条件时形成新版本，同步核验输入、标答与评分。缺关键依据不能仅靠“消歧”写成已知事实。[S011 L10–11、L65–67；具体工具偏好未采用]

对核心材料做贡献检查：删掉或替换它后，哪个业务判断失去依据或应改变？重复披露可支持一致性核对，不能算成新增独立风险证据。背景材料可以保留，但不把文件数量或引用次数当作复杂性证明。

顶层 Markdown 可能同时含题面、评分、思路和答案，不能整份作为作答输入。先按语义拆开并人工回读边界，再由显式清单指定题面、业务输入、公开模板及私有评判角色；文件名前缀和路径名只作线索。业务摘要、现成汇总和合法结论是否属于正常输入，应看业务责任，不能为降分一律删掉。

在教师副本尝试正确短答、只读摘要的合法答法、合理替代解释和有据拒绝。如果它们已充分完成公开任务，应按同一标准接受；只有确实缺少某项必要责任时才据此调整题目。不能为了强迫长推导而新增隐藏要求。

## 公开材料中的制作声明

公开业务材料同时检查制作方式或来源身份的自述。范围包括题面、业务附件、说明及拟交付文档中的正文、README、文件名、页眉页脚、全部工作表、注释及可读属性。清理 AI／模型制作、来源／真实性自述，以及 synthetic／constructed／模拟／演练／仿真等同类声明；不换成隐晦同义声明继续保留。此项属于材料表达规范，不宣称是任何平台通用政策；有明确相反的项目交付要求时应先核实要求冲突，不能伪造处理结果。

逐句核对声明承担的业务作用。若同段还提供必要数据、执行范围、对象状态、适用边界或验收条件，先把条件重写为直接业务事实和委托要求，再清除声明；无法分离时，在新版重构为不含此类自述、仍完整可解的材料，不把“必要”作为原声明继续保留的理由。私有来源、设计或替换范围及验证记录单独保存，不随待清理交付材料混入；清理不能新增真实采集、正式签署或生产已执行的无据主张，也不改变本批材料制作的授权范围。

内容检查者沿已有 issue／record 留下文件精确位置、原句、处置及必要条件保留依据，交现有作者／返修角色集中修改，再从保存原件回读关闭。已锁请求、在途冻结输入、旧答卷／原评及历史归档不就地覆盖；新要求进入下一可修订版本，必要时同步附件、引用及版本说明。没有发现只报告实际读取范围；这项检查不新增评分要求或终审层，也不代替泄题审查。

## 模型可见材料的整包复审

采用[S015第2–4、7–8条](../experience/S015-whole-package-review-prompt.md)补强[S008十步流程](../experience/S008-ten-step-workflow.md)。在初稿形成后、每轮投测前、返修后和最终交付前，通读当前题目、实际请求与全部模型可见附件：表格包括全部工作表、可见单元格及注释，其他格式包括实际可取得的正文、图表和附属内容。查找同类问题后按文件集中修订，不只搜索关键词、看首页或复查上轮改句。相邻阶段同字节且刚完成的审阅可以复用，但新的线索须回到相关全包关系。

本检查单独回答“公开输入已经完成了哪些工作”。私有文件隔离、数值正确、规则合法、原案例通过或作者独立重算，都不能代替这个结论。题面与附件提供给作答者；下述归属记录、难点和反例只保存在现有教师侧record或business审查证据中，不新增对外附件或另一套审批流程。

### 公开材料的加工边界

先完整完成业务设计、私有参考和正常对照。公开材料的完整，以事实、条件和可取得的证据足以完成委托为准；拟测的对象归口、关系映射、适用性核验、证据取舍、方法选择与方案判断，留给作答者完成。收回作者预先加工的分析成果时，恢复相应岗位当时可得、足以核验和推导的记录，不以减少文件、打乱数据或改成同事口吻代替责任恢复。

区分**核验所需条件**与**本案核验结论**。目标、字段、制度公式、权限、当前状态、时点和必要关联依据应明确；“本案记录全部齐全”“这些版本均适用”“不存在跨对象干扰”等保证，若正是拟测判断，应提供能验证或反驳它的原件，不同时无条件担保其正确。确需给定的设计假设或真实上游成果可以保留，注明其适用范围并扣除它承担的工作；任务实际只测给定前提下的执行时，如实限定能力声明。

正常业务台账、读回汇总、系统键、分组和岗位意见不一律删除。核谁在何时、依据什么提供，委托是直接使用还是复核；需要复核时保留相应原件和关联线索。可保留有来源的局部意见、版本差异及未核状态，不能用作者整理的最终调和结论替代作答者判断，也不能刻意造冲突、隐藏参数或删正常关联键。证据不足以支持唯一裁定时，补足事实或接受有依据的条件分支。

沿下方同一责任表记录：旧公开位置及已做工作 → 实际改动或有据保留 → 作答者剩余判断 → 对范围、执行、资金、承诺或验收的影响 → 必要条件与正常路径复核。仅删提示或让材料不整齐不算增难；须从保存的新原件验证责任确已恢复。该记录只供教师侧作者、质量与内容检查使用，不加入作答或首轮独立事实评阅的请求。

### 核心判断归属核对

对本题声称要检验的每个核心判断、关键增难点或受返修影响的责任，用具体业务动作表述，例如“从签署范围和队列负载确定仍可能发生的变更”，而不是“跨材料推理能力”。沿公开原件及实际或教师成功解法填写下表；可直接扩展现有设计底稿，不要求固定数量。没有真实答卷时注明解法是教师推演，不能称实测。

|核心责任及交付后果|公开原句/字段定位与性质|输入已完成的工作|作答者仍须完成的关系及路径|处理决定与复检证据|
|---|---|---|---|---|
|稳定责任/考点ID、需形成的判断，错误影响哪个成果|文件版本、段落/工作表与单元格/列名及代表业务键；引用原句或字段值，并按下述性质区分|哪些识别、核验、归口、映射、排序或结论已由输入给定|要结合哪些原件、适用什么公开依据，怎样得出本案结果；已有答卷定位其实际使用处|保留/删冗余/恢复原始依据/缩小能力声明；最终输入定位、必要条件及参考复核结果|

按内容的实际作用区分，不因文件名叫“制度”“交接”或语气像同事就放行；同一段可包含不同性质：

- **原始事实和正常记录**：当时可得的合同、签署、流水、日志、字段定义、范围和状态。保留能支撑决定的金额、单位、时点、权限、否定、期限、班次、已有承诺及必要关联标识。
- **必要外生制度和工具契约**：企业专属公式、费率、法定或约定优先级、强制流程、接口行为及操作先后。说明业务用途和适用范围；自定义题设制度须处于本批制作许可内并保持自洽，不能仅因作者把正确做法写成“制度”，就声称相关方法选择仍需作答者独立完成。
- **上游已完成成果**：已核完整性、无干预保证、已清洗台账、经济归口、统一对象映射、汇总、诊断和方案。核谁在何时有依据完成；可以作为正常输入保留，但其已完成工作从待测难点和能力声明中扣除。若委托是复核它，应提供能验证或反驳它的原件，不能同时将其无条件担保为正确。
- **本案推导、预填结果或定向防错**：具体对象的冲突解释、适用分支、正确结论、完整求解流程，或事实充分后再写“不要采用某错法”。确认它是否正是本轮要求作答者发现的内容，不能换成邮件口吻、另一列名或另一附件继续保留。

### 合并材料检查剩余工作

逐段分类后，沿最终公开包把核心责任实际走一遍：是否仅靠已核保证、已归口金额、统一映射和现成算法，就能跳过设计声称的判断？答案或中间结果是否藏在另一张表、公式、标签、文件名、说明或摘要里？多份材料之间有依赖，不等于作答者仍需发现这条依赖。单句各自合理，也可能组合成完整答案方向。

将得到的最简合法路径与归属表对照。若只需实现给定算法，准确写成规则执行和成果建设；不能继续声称在测适用模型选择、证据核验或独立诊断。制度执行本身可以有业务价值；是否值得继续投入按[研发决策](difficulty-design.md)判断，不以脚本短、可批处理或本轮做对自动淘汰，也不恢复“局部先错才制作”的门槛。

例如，已提供每份合同正确归属的收入和费用，就不再把“识别费用何时发生”计为未完成的难点；接口一般语义和队列原件应保留，但作者再次解释本案某工作项与新签署的冲突，会提前完成二者的联结。这两个对照用于识别责任归属，不要求所有题拆掉正常财务台账或业务交接。

### 修订时保留条件，收回预解题

对归属不符的内容逐项选择，先解决业务目标，再编辑：

1. **代做拟测判断的提醒或重复推导**：对仅复述本案正确路径、结论或定向防错的内容，核其确可移出后删除，并定位仍然充分的公开事实和制度。未替作判断的必要截止、权限、状态或范围说明可以保留，不因没有新增事实就一律删除。只删“不要”或改写语气不算修复；同类提示及其他文件里的等价预解结果一起核查。
2. **正常且必要的上游成果**：保留它，缩小相应能力声明，使评分验收实际剩余责任。若它已承担本轮主要目标，回到任务范围/投入判断，不用增列、重命名或加格式要求假装恢复难度。
3. **本轮确需作答者完成的判断**：在新版本提供该岗位实际可得、足以推导的原始依据，将本案关联或裁定留给作答者。在本批允许范围内可设计完整记录并验证，不要求用户补私人材料；不能只删结论而不补证据，也不为迫使某种解法删除合法替代路径。
4. **没有公开依据可以唯一裁定的条件**：补事实、字段或必要制度，或在标答和评分中接受有依据的分支。补充后同步记录哪些解释工作已由输入完成。不能保留使任务无法合理裁定的矛盾、缺条件或隐藏参数来制造难度。业务记录中的错误、冲突和不可靠意见可以保留，但须有足够公开依据供辨别，并在参考中接受有据分支。

范围、单位、ID、时间、否定、权限、效力、资源、价格、合同责任及必要工具语义逐项做修改前后核对。每处删改须说明哪些事实仍保留、原依据在哪、正确结果及合理分支应否变化；业务条件改变时形成新版本，同步受影响附件、参考与评分，保留旧题旧卷旧成绩。

### 复检与关闭

从最终保存的公开原件重建受影响判断和完整依赖，核对标答、合法替代方案、正常分支及易混条件。涉及计算须复算；涉及语义由审阅者说明如何从公开证据走到结果。新上下文复核遵守主skill的公开输入边界，不能把归属表、私有难点或参考先传过去再称独立求解；共享目录的权限局限如实记录。

在现有record/business审查证据中保留本轮阶段、输入版本/摘要、整包读取范围、归属表、实际修订定位和复检结果。**核心目标仍被输入代做却继续按独立判断宣称、所需公开依据缺失、必要条件未核，或只写“无泄题”而没有对应位置与剩余路径时，business审查不得标为passed，不能据此按同一难点进入正式投测。** 应完成修订，或明确改变任务/测量范围后再审；其他已通过的数值/格式检查只保留其各自范围，不覆盖此缺口。程序check不能自动作出该语义裁定。

出题总指令、教师检查清单和其他答卷不发给作答模型。闭合本检查证明输入责任与当前任务一致，不证明难度达标或删提示后必然低分；难度结论仍来自相应版本的真实运行。

## 难点应落在必要处理链上

具体选择或修订增难机制时读[业务增难机制与验证](difficulty-design.md)：对齐对象与口径、时点/权限/效力、状态变化、方案可行性和跨成果依赖，并以正常对照核验。S010补充完整经验文本；每个机制仍需能落到正确处理、错误后果和可观察验收，不采用“至少三个因素”的通用门槛。

复审重要增难改动时，从保存的题干、业务记录、参考结果和考点核对实际落实：旧成功路径哪些仍有效；所选方法改变了哪条必须处理的关系；证据关联是否仍由作答者完成；合理错法或反事实怎样改变主交付；当前评分是否验收这些责任。若设计底稿声称共享或继承，实际材料却允许独立处理、已经给出本案结论，或复杂支线可合法跳过，按证据纠正设计判断，不因用了机制名称就通过。不强制所有正常输入都原始化；有据的替代解按同一委托接受。核验结果与材料位置记入现有审查记录。

S002 要求专家自己保留 8–15 个隐藏难点，每个关键难点至少被一条考点覆盖。这是该文档的检查项，不能自动跨期泛化。建立 `难点 → 所在明细 → 模型必须做的判断 → 正确依据 → 考点 → 失分证据` 的映射；隐藏清单不发给作答模型，但判断所需事实和规则必须在输入中。[S002 E11、E14]

| 文档中的难点类型 | 需要模型实际处理什么 | 必须提供的依据 |
| --- | --- | --- |
| 材料冲突 | 区分草稿、消息、正式版本，选择适用资料 | 明确版本、效力优先级或对应业务规则；不是让模型猜 |
| 口径不一致 | 对齐含税/不含税、币种、订单/实付等 | 足够推导换算关系的业务资料和定义 |
| 状态误判 | 区分待批/已批、计划测试/已测试等 | 截止时点、状态定义、证据和例外说明 |
| 惯用方法失效 | 简单排序/分摊无法满足多约束，压力情景需重算 | 预算、产能、起订量等真实限制及情景变化 |
| 假异常 | 不把正常空值、默认条款误报为风险 | 能判断正常/异常的资料依据 |

“别在题面点破坑”指不提前告诉模型哪一行有错、正确解法是什么；不代表删除预算、截止日、材料优先级等必要规则。多份交付物只有共同服务业务目标且需要互相校验时才有意义。[S002 E01、E10–E11；本地解释]

对参考或设计中的排他主张（如“只有某桥表才能关联”“某字段必不可少”），核验一条正向路线正确还不够。沿最终公开原件列出可能承载同一事实的标识、历史摘要、标签及组合字段，按作用域和时点检查候选对象；必要时以保留合法契约的反例验证。记录“充分的一条路线”和“确有证据的必要条件”，不把独立求解使用作者路线当作唯一性证明。发现等价充分路径先纠正参考或评分；若它使拟承担的判断可跳过，再调整业务依赖，不删必需字段或评分强制路线。检查应覆盖替代标识和字段组合，但不要求每题穷举全部关联算法，也不将唯一候选等同业务授权。

## 对齐题干、材料、标答和考点

对每个重要考点建立一条可追溯记录：

`题干要求 → 输入证据位置 → 允许的推导/假设 → 标答结论 → 可判定考点 → 分值`

对计分的中间推导，再做一次替代证据验收：从题干业务目标出发，尝试不展开该推导、改用另一组公开证据的答案，核它是否仍能支持实际决定及全部必要责任；能完成时，不把材料提供了某个公式、字段或概念当作必须逐一复算或讲解的依据。若确需该推导，应说明遗漏会使哪项业务判断失去支持，不只在对照表填一个来源位置。该核验用于确认必要责任，不要求所有题加入特定分析方法或固定考点。

评分校准时另核“没有复述条款”和“没有履行责任”的区别：对拟因省略扣分的点，先定位公开要求是否必须交出该数值或对象，或答案是否已通过完整批准、命名且有对象与前置条件的公开操作履行契约。以同一答卷构造最小相反指令比较；若正例只缺原文而行动已合规，不能照负例扣。反向行动不能由默认契约抵销，明确要求的实际记录也不能靠空泛“按规定”补齐。保存具体责任证据及正反差异，复核后再汇总，不据此改变冻结权重。

检查双向覆盖：题干重要要求应有考点，考点也必须能回到题干或其明确业务目标。若标准依赖专业常识，说明适用条件；不得悄悄增加只有评分器知道的要求。附件中的答案/结论是否属于合理业务输入要逐项判断，不能为降分删掉正常必需的上下文。

区分评分维度与考点：准确性、约束遵守等维度用于分组，每个维度下可有多个可判定考点。不要把“准确性”这个标题本身当成完整验收条件，也不因同一错误落入多个维度就重复计罚。S005 给出了维度/考点的层次关系，没有规定固定数量或权重。[S005 E17；重复计罚处理为本地方法]

按任务实际责任，在作答前写清评分对象、时点和证据：陈述是否正确、需要在何时作出判断、实际执行了什么、最终状态是否合格，以及错误后的补救是否有效。只定义本题涉及的责任，不要求每题拆成五项或等权。说对不自动代表做对，事后承认不撤销已执行的错误；有效补救可按预先标准得分，但不能因此抹去过程责任或重复惩罚同一错误。

按 S002，该文档要求先于回答建立总分 100 的标准；总分 100 是来源范围内的要求，本地执行层按单题明确配置检查，兼容通过案例中的 28 分等分制，不私自归一化。考点客观、正交、一条检查一件事，可判 TRUE/FALSE。把事实正确性、数值容差、约束遵守和交付可用性拆成可观察的判断，不用“充分考虑”“分析全面”等印象词。涉及数值写清单位、小数位与容差；例如“考虑税差”不能替代对具体不含税金额的验收。[S002 E02、E12、E14]

半开放题允许不同但合理的路径，不能将样例选项或表达强制为唯一答案。评分形式需注明依据：S002 明确采用原子 TRUE/FALSE；S003 允许区间制/禁止项；S005 53:01–53:42进一步说明尽量客观但特殊情况并不禁止分档，并要求明确什么条件对应哪档。采用区间分时，作答前写清可观察条件、边界和分值；没有可靠档位依据时可拆为预先赋分的原子考点。多档评分不等于临时按印象打分。[S002 E02、E12；S003 E03；S005 E14；冻结与边界核对为本地方法]

采用“按正确对象或任务比例”时，在冻结前给出业务计数单位、分母边界和归并办法；以公开必需责任或实际选择的独立操作为单位，不按答案的行、表或句子计数。同一持续操作拆写、合并写或增列正常说明不得改变得分；按类别封顶时，也应区分同一根因传播与多个独立错误，而不把同属一个标题当成同根因。用等义拆合正例和独立错法重放，不能稳定判定则改为明确原子条件或固定档位，另版后采用；不得根据本轮模型表现改旧权重，也不把计数缺陷解释为分值必然过低。

核验可替换组件或同名模块时，把实际加载对象的文件路径、函数定义来源与最终被评文件 SHA 绑定；仅记录磁盘目标文件的哈希，不能证明执行的就是它。合法转发或共享 helper 须追踪实际依赖，不把入口与函数同文件当成评分条件。被评脚本可能改变模块搜索路径，应采用明确文件加载或等价可靠装载，并以正常正例检查。错载结果保留标为无效，修复绑定后重放原例再作业务裁定；不要求为纯文书题增加组件工具或执行附件代码。

代码相关部分按功能行为、约束和实际结果验收，不能要求与参考实现逐行相同。S005 讨论代码错误时关注它是否影响任务结果，并仍建议部分代码/方案类任务；不能从听众“一行错就不能运行”推出所有代码错误均应整题零分。[S005 E11、E14；按行为验收为本地解释]

S003 35:24 提到严重踩雷可整题归零、普通错误仅对应考点归零，但未给严重错误类别、触发细则或官方实现。本地采用归零规则时，须提前说明业务上的致命后果、证据条件及影响范围，并避免重复惩罚；这些是保障可复核的操作建议，不是已取得的官方归零公式。不能为了低分把普通错误升级为整题归零。[S003 E18]

S003 允许提交前完善新发现错误对应的考点，也强调不得为压分歪曲质量。发现错标答、漏检或不合理权重，可以修订标准，但本库将其另存新版本，保留旧成绩及修订理由；同标准评分纠错或新标准复判分别留存，不冒充新运行。修订后先完成受影响的质量复检；是否投入新版自测统一按[研发决策](difficulty-design.md)，需要取得新版难度结论时必须用该版独立运行。未运行保持未测，不把旧低分迁移到新标准。这个版本管理办法是本地约定。[S002 E02、E10；S003 E07、E10]

[S015第5条](../experience/S015-whole-package-review-prompt.md)的已证实错漏用于检验和修补覆盖，不能成为评分项的唯一来源。首次投测前仍按完整业务责任建立评分尺；已被正确识别的错误只留证，不机械增项。不为凑数量加入无实质责任的常规项，也不因模型上轮答对而删除仍重要的权限、金额或交付验收。任何新规则进入新版本，原答卷和原成绩保留。

用标答检查 rubric：如果高质量标答被大幅扣分，先核对标答、题干和评分器；不要先认定题目很难。新标准冻结前，再选少量与本题有关的教师反例，如说对但做错、错误后仅承认或已恢复、结果正确但缺必要证据、合法替代路径，对照预期得分与业务是否可验收，检查规则能否区分这些情况。这些构造答卷只校验评分语义，不算模型实测。发现标答或规则缺陷，修正并升版本；已有答卷才暴露的歧义另记解释差异，不追补旧时点或覆盖原评。AI 对标答的评分仅作辅助，事实与业务正确性最终需专家校准。[S001 E22；反例校验为本地方法]

### 教师侧的评分校准

在现有教师质检中，对本题可能产生争议的规则验证以下两类边界，保存具体公开条款、候选成果与判定；不是再增加一轮目标模型调用。

- **责任范围**：按对象、阶段、时点和触发条件核公开依据。初报条款不自动扩成每次更新义务，事故交接不自动扩成正常通知，参考中的岗位分工不自动成为必须新增的工作。发现一处扩张后检查同类规则，修新候选而保留旧冻结及原评。
- **等价成果**：用同一业务结果的展开、合并、跨表或明确算式呈现作正例，再用缺少关键判断或明确反向动作作反例。若对象、单位、期间、状态和所需运算关系已明确，验收允许专业等价表达，且无需评阅人补新的政策、归属、授权、假设或业务选择，不因缺一个参考表头或重复差额扣分。若还须重新选择适用条件、判断新时点余额、补一项方案，或公开要求的实际操作/必要机读交付未完成，则不是等价省略。错误公式或反向指令与正确结果并存时，仍按其实际冲突及预设责任裁定，不能一概豁免。

校准应实际比较正反成果，不只手填若干 FALSE 项加总。可复用范围适用的教师侧校准材料并记录依据，但它们不是新增平台规则或目标成绩。历史答案、纠分结论和本题预期结果不得传给作答者或独立首轮事实审查者。独立评分第二阶段只取得同版冻结参考与评分尺及[中性评分交接](../templates/role-handoffs.md#独立评阅第二阶段)，不取得作者既有分数或错误清单。

## 审查输出

给出“可进入探索性压测 / 需修订 / 不适合当前收题范围 / 证据不足”及理由，不捏造通过概率。每个重要问题写明具体位置、为何影响可解性或评分、最小修复建议以及需补的证据。

评阅实际答卷时，分别报告按冻结标准得到的分数，以及业务成果能否直接验收、还需修复什么、已产生何种后果。高分不自动代表业务无缺陷，业务不可直接验收也不自动触发整题归零；以原先明确的评分规则裁定分数。

纯审查委托在此交付发现；实施或持续研发委托则按[闭环执行](difficulty-design.md)接着修订、回读和复检，在现有记录中保留实际关闭证据。审查报告不是修复完成回执，候选不再投入也不等于总体目标完成。

即使准备度较好，也只表示本地检查结果，不能代替官方质检或实测难度。必要时可以先做小范围试解以发现材料问题，但材料失败不得作为有效难度成绩。

S006 I02 的共享流程补充：先核内容底稿、来源映射、输入/答案隔离及最简合法解法，再制作正式交付文件；质量复核看过答案的试解不算盲测。有运行产物后，按[压测后复盘](post-run-review.md)通读整份答卷，检查考点之外的错漏与正确反例，修复覆盖和可解性问题；后续纠错、重新设计与投入选择按[业务增难机制与验证](difficulty-design.md)执行。[S006 I02/I03；本地提炼，不是官方新增要求]

## 保存原件与交付状态核验

依据[S008步骤4、6、10](../experience/S008-ten-step-workflow.md)提炼：制作完成后重新打开最终保存的原件，检查内容、公式/重算结果、跨文件引用、版式和可读性。压测与交付应对应这些原件的版本，不能只检查编辑界面、草稿或导出的预览图。WPS是该分享者的工具选择，实际制作工具按用户要求和环境确定。

按当期平台字段建立“题包版本—填写文本—附件栏目—压缩包内容”的对应关系，确认没有漏件、旧件或输入/答案混放；只在平台需要压缩包时制作，压缩包不取代要求单独上传的栏目。填写保存、检测结果、正式提交、审核结果各自保留可见回执/状态及时间；无证据则标未核实，不能用填完或检测通过代表提交/审核成功。具体顺序和触发条件以该平台实际规则为准。该检查方法不改变已有外部操作授权边界。
