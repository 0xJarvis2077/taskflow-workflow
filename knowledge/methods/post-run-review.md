# 压测后复盘与修订

公开方法。参考 S006、S007 的完整读卷与经验积累方法，吸收 S010 的事实／假设区分及实际返修原则，补充独立两阶段评阅、过程绑定和版本管理。来源类型与采用限制见[经验来源索引](../experience/index.md)。同场会议、截图和派生整理不重复计为独立证据；以下执行约定不代表平台新增要求。

## 1. 先确认本次运行能说明什么

核对出题、质量审查、作答、评阅及发生时的争议复核身份/会话或运行 ID、各自实际可见范围和干预；将原始请求、冻结题包与rubric、实际模型/工具配置、收到的输入和读取结果、完整回答及交付物、可见轨迹和停止状态绑定到同一次运行。评分资料的版本可先核清单或摘要，独立首轮事实审查仍按下文顺序暂不读其内容。区分“文件已上传”“模型可读取”“模型实际读取”；模型在可用材料中主动漏读可能属于能力问题，上传或解析失败则先查环境与输入问题，不能一律算作模型不会做。[S006 I03；角色与绑定方式为本地执行方法]

检查评分资料、历史答案、共享记忆是否泄漏。仅创建新文件夹或提醒不看答案不能证明隔离。质量复核可以查看题干、标答和全部评分资料；其试解结果不能冒充独立盲测，作者复核也不能替代未见作者结论的独立首评。训练性质的公开重建、参考核验与目标模型真实答题分列用途，不迁移分数或角色独立性。缺关键记录时保留可证明的局部观察，整体结论标注无法判定或仅探索，不补造过程；运行条件及角色边界按[压测方法](stress-testing.md#三角色的信息边界)核验。

先核过程采集实际覆盖：可见工具请求及返回、检索结果与打开内容、脚本/中间表、最终文件与可见修订时点、业务理由。调用参数不等于返回内容，局部日志不等于完整轨迹；缺失 tool response、某一步读取结果或内部推理分别标未知。可以从原件追加带出处的提取索引，不能反填成当时已采集。若目标运行仍在进行，仅做旁路读取及追加审计，不更改冻结输入或运行依赖；采集不足在下一次获授权运行前修，不能因此自动重跑。

### 逐判断依据的提取与后继使用

沿现有事实和责任记录完成两次交接，不另建评分表或审批层。首轮独立评阅按公开委托识别重要判断，复用事实 ID，关联公开原句／字段及其组合、实际读取／引用／计算／操作、最终成果与是否已纠正，覆盖重要正确工作、错误、遗漏和未知。逐字引文须与实际定位原文一致，摘要、箭头关系与事后推断分别标明，不能用摘要证明原文直说了结论。工具证据定位到实际响应、事件 ID 或行号；只列调用命令不证明返回了什么。仅能核终稿时明确过程未知，不从结果反推模型如何思考，也不先接收私有难点、考点或旧分。

事实封存和原评保存后，作者及内容检查者将上述记录接到同一份核心判断归属表：公开材料已经完成什么，作答者实际又建立或执行什么，哪些仍无法判定。分别标注原运行、终稿、评阅阶段反例和事后重建；看到材料被读取、脚本与材料一致，可支持可见处理判断，不能直接证明某句是成功的唯一成因。必要制度、正常上游成果和合法替代仍保留，已由输入承担的工作从独立难点声明中扣除，旧卷照冻结标准保留得分。

作者据此逐项形成下一版实改或有据保留，引用原事实和责任 ID，写明改变的业务关系、材料位置、保留条件及正常分支。内容检查者核公开预解题及实际修改，独立复检仍沿既有范围签发；没有改动或复检证据时保持待核。主控接收该证据选择下一投入，不重复评分。依据链必须被后继使用，不能只在报告中收集完就结束，也不能以索引齐全证明题目已变难。

已经完成的答卷优先消费原始档案，追加有父文件摘要和定位的事后提取，不覆盖原事实、原卷或原评，不为补索引自动重跑。正式作答只完成公开业务委托，不增加教师依据表、逐步反思或隐藏考点提示。新请求采用本方法前，由工程核实际生成入口和冻结依赖，在隔离副本验证后接入未来派工；仅改方法文档不等于已经生效。

### 从真实成功路径复查公开预解题

每轮读卷都复查核心成功方法，不等到连续满分才开始。连续满分是调查线索，不是泄漏证据。从四个互补审查面核对：实际请求/上下文和可见读写轨迹；公开材料是否代做本案判断；完整终稿及冻结评分是否判对；合法成功方法实际还需要哪些独立推导。区分“实际读到私有内容”“存在可复现暴露但未见读取”“公开输入提前解释了方法或提供已加工结果”“未证实的通道风险”，不要合并成一个泄题结论。无私有读取、材料被称为制度、标答与答卷数值正确，均不能关闭公开预解题检查。

从已归档原件复核，不只读取前轮 `passed` 摘要。独立首轮事实审查与首次评分保存后，再对照投测前的教师侧“核心判断归属”记录；沿最终脚本、引用、计算和成果，补实 `公开原句/字段及跨文件组合 → 输入已完成工作 → 本卷实际处理及证据 → 终稿结果 → 业务后果 → 下版动作/正常对照`。检查全局保证、已清洗或已归口字段、预建对象映射、完整算法、个案冲突解释及定向防错的组合影响；逐句均可称为合法事实，不等于组合后还留有原来宣称的判断。没有可见过程就限定证据范围，不推测隐藏思维链。

按实际结果更新该记录：核心判断确由模型完成、输入已提前完成、仍无法判定，并据此修正能力声明和下一投入。正常上游成果或强制制度可以保留，已由它们完成的工作不再算独立难点；按公开条件合法作答仍照冻结尺给分，不因现在发现输入太充分而追扣。一个策略生成多张表不证明多个独立难点；共同公开来源、必要算式和模板相似也不证明复制私有答案。

依[整包复审](design-review.md#模型可见材料的整包复审)决定如何修复，不把预解题一律简化成删句：无新增事实的提示可删；正常上游成果可保留并缩小待测责任；任务确需作答者独立完成的判断，要补齐可核原件并在新版恢复责任，不能只删保证或结论后留下空白。对特定提示做诊断时保留事实、原评分和结果判定，先核必要条件，再在授权内运行。删去部分提示后仍正确，仅限制这些改动对该次成功的解释，不证明剩余字段和全局算法未代做工作。已见教师资料的审阅者不能再自称盲解；需要独立公开重建时另用只见公开输入的新上下文，记录实际权限范围。静态发现与实测因果分别留证。

## 2. 通读整份答卷，再核对评分覆盖

独立评阅者先只基于冻结公开输入、原始答卷、实际交付和可见过程，逐项检查业务结论、计算、状态/版本/时间口径、跨文件一致性和交付可用性，保存首轮事实记录；此时不看作者已有分数、复盘结论、私有参考或核心判断表。首轮事实封存后，由同一模型、同一实际 SID 读取冻结参考与 rubric，形成并保存首次评分，核查参考错误、允许替代解和评分覆盖。主控只做技术证据接收和研发调度，作者依据结果复盘；无具体争议不再加全卷复评。有实质分歧时按[主控职责与争议处理](stress-testing.md#主控职责与争议处理)交新的独立角色核验，不由主控或原作者直接改分。首轮事实记录可以留未决，不强求在没有参考时猜评分。已经接触作者结论的评阅据实标为作者复核或非独立评阅，不事后改名。

既检查已有考点，也记录其外部的真实错漏和合理替代解；新增发现必须能回到题干要求或明确业务责任，不能临时创造隐藏要求。[S006 I03；先事实、后冻结尺与条件式独立争议复核为本地方法]

| 诊断类别 | 要确认的内容 | 下一步 |
| --- | --- | --- |
| 已覆盖且命中 | 预设考点确实识别了有业务影响的错误 | 保留错误与判分证据，核验是否与其他失分同根因 |
| 已覆盖但漏检 | 标准已有要求，评分过程却未正确识别 | 修评分执行或歧义，记录复判依据 |
| 未覆盖的新错误 | 答卷存在真实任务错误，现有考点未覆盖 | 核实责任与影响后修订覆盖，另存评分版本 |
| 正确反例/替代解 | 模型使用不同路径仍正确，或本应正常的情形被误判 | 修正错误标答、过窄条件或评分误报 |
| 环境/执行异常 | 输入传递、权限、工具或服务异常影响作答 | 先定位外部原因；与能力失误或未知原因分开 |
| 处理过程未知 | 结果可核，但缺工具返回、中间产物或其他实际处理证据 | 保留可核结果及其分数，限制路径归因；不能自动算错或补造已完成判断 |

复用核心判断归属表及已有证据，不另建一套门禁。将首轮观察接到对应业务责任：`公开依据 → 实际处理及证据位置 → 终稿结果 → 业务后果 → 下版动作/正常对照`，同时记录正确、错误、遗漏和未知。引用、工具实际返回、脚本、中间表、文件修改时点及最终文件可以支持处理归因；可见文字理由与执行证据分开核实，最后答案正确不证明所有中间判断均已独立完成。正常结果和最短合法成功路径也要回查；本卷实见路径、审查者另行重建的可行路径以及仅有假设分别标明，不以作者重建冒充模型真实过程。上述类别只诊断覆盖及证据状态，不替代题目、标答评分、环境、能力、混合未知的根因分类。

不为留证向作答者追加逐步反思、隐藏考点或目标分数提示。事后追问的回答只作辅助解释，另记时间与上下文，不能改写原运行或终稿，也不能把推测变成原始操作证据；不获取模型隐藏思维链。没有完整路径时可据原件判断交付正确与否，但应保持对应归因未知；公开责任未要求说明的处理不能仅因缺少解释而扣分。

把同一上游错误及其连锁后果关联起来，不当作多个独立根因重复计罚；只有额外违反了可区分的验收责任，才按预设规则分别判断。复杂推导可以涉及多种业务条件，评分项仍须可独立验收，不能为“每考点至少三个维度”的个人建议硬凑复合条件。[S006 I03；S007 E22]

[S011 L70](../experience/S011-expert-materials-skill.md)补充区分根因诊断与成果验收：写对条件或公式不能替代正确实际结果。连锁错误须标明上下游依赖，按预先定义的可区分业务责任判定；同一输出同一错误不能换名重复扣分，也不能仅因根因只有一个就豁免全部交付责任。已覆盖且正确识别的模型错误可只留证，不因L31“完善原子规则”的表述而机械新增考点。

以最终答卷和实际交付文件判定成果；草稿错误若已被终稿正确替换，不将其冒充最终错误。当答卷先执行错误、事后认识正确时，按冻结标准分别核对陈述、决策时点、实际操作、终态及恢复责任中已定义的要求。事后承认不能抹去已发生的业务错误；旧标准未明确的时点或扣分条件也不能追补。保留有证据的评分分歧，下一版按[评分设计](design-review.md)澄清。另报业务交付能否验收及剩余缺陷，不能用高分代替无缺陷结论，也不能因一项严重错误临时整题归零。[S015第6条补充终稿边界]

## 3. 先修质量问题，再考虑下一版难度

每轮同时复盘题目和实际工作流。对发现回查研究、设计、独立核验、整包质检、运行隔离和评分中原本应发现它的环节；区分当时尚未执行、已执行但漏查、方法范围不足、职责交接断开及规则错误，不以现在知道的答案倒推前序都应知道。已证流程缺陷修对应方法、模板或工具，并用原问题及正常对照回放，记录“缺陷证据—原因—实际修改—验证结果—后续表现”。下一轮查复发，复发则重新定位，不只加提醒。没有证据时保持未证实，不把模型强或单题偏易自动归因流程。

质量纠错优先修歧义、缺必要材料、不可解约束、错误标答、漏检和正确替代解被罚，采用恢复原任务含义的最小必要改动。为定位特定原因的诊断实验也可控制改动范围，但须说明它回答的问题。完整业务重构可以同步调整相互依赖的责任、材料关系和验收依据，不必为了单机制归因拆散任务；具体投入选择统一见[研发决策](difficulty-design.md)。一次错误不足以说明整题都应围绕该点重写；已稳定做错的点也不必继续叠加难度。[S006 I03；S007 E18；改动范围区分为本地方法]

在实施或持续研发授权内，按[研发决策中的闭环执行](difficulty-design.md)将发现接到实际修订和复检；同一问题保留改动版本与关闭证据。仅记录问题或完成本轮报告不关闭未达成的总体目标。复检未通过继续返修，候选结束则承接总体目标选择下一动作；具体停止和授权边界统一由该处维护。

“没有质量缺陷”只支持对应质量结论。下一项工作统一回到[研发决策](difficulty-design.md)，分别报告质量、实测难度与投入选择。比较可迁移的成功方法及主要责任覆盖，不等到整题满分或旧脚本可原样复用才降低重复投入；局部正确也不外推未测责任。累计核对历轮解释的预期与实际结果，改进落实仍无预期效果时降低原解释的确信。写清下一步实际选择研究、诊断、重构、制作还是结束候选方向及其证据用途，不能从“总体目标未达”直接跳到下一版调用。流程规则修复还须按该处方法回放决策，并检查应继续的对照情形；文字修改与后续真实效果分别验收。

S010第3.8节要求把“实际错误”与“为何出错的假设”分开，第6.4节明确处理决定可以是不迭代：新发现只有在与任务责任相关、证据可复核且后果明确时才进入设计。按业务重要性、未覆盖程度和修复收益选改动；已有错误没有新的重要未测边界时可保留，不能让下一版只服务少数已知错误。需要选择机制时见[增难方法](difficulty-design.md)，不为因素数量硬造依赖。

追问出题模型“为什么容易答对、还有何遗漏”所得内容，先当候选解释。回到具体输入与最终产物位置、公开业务责任及影响，检查支持证据、已有成功路径和可能反证，并与已登记问题去重；追问次数与多模型一致意见本身不增加事实依据。缺证保留为假设，说明能核实它的下一项证据；允许得出“未发现新的重要问题”，不能为响应追问凑发现或自动开一轮改题。研究性的设计假设仍可在相应范围内验证，只是不预报其效果。复用原record中的观察、原因假设和关闭记录即可。[S016第4条；本地接入]

必要标准、适用版本和正常业务上下文应保留，同时核它们已承担了哪些目标判断；“合法可提供”不等于“未提前完成待测工作”。检查最简单的合法解法：若脚本即可正确完成任务，应承认该路径有效，再区分脚本实现了模型独立建立的关系，还是公开给定的完整流程。不能禁用允许的工具，或把规则执行题继续描述为独立建模题。附件数量、体积、格式和相似度不能替代业务判断；10份、2MB、30%/40%都不是本库门槛。删合理“送分项”、按错误加权、转PDF制造解析负担，也不能成为增难手段。[S007 E07、E09、E12、E15、E24；公开输入责任审计的本地修复]

### 验证流程修复是否实际生效

沿已有问题关闭记录分清三种证据：规则/模板已修改；实际新派工或主控接收已使用该版本；新的独立成果是否避免同类误判、支持原定业务判断。记录各自日期和证据位置，不能用前一项代替后一项。利用原问题和正确/错误对照做回放，见[教师侧评分校准](design-review.md#教师侧的评分校准)；回放验证规范，不充当新版目标模型压测。

下一轮复发时检查实际发出的角色请求及接收产物：是未接入修订、作用范围误解、等价判断失当，还是规则本身不足。修复具体交接或判定依据，不继续叠加同义提醒。评阅纠错率、等待时间可辅助查执行；题目是否变难仍以有效答卷中的重要业务错误及公平评分验证。监控沿现有记录跟进实质变化，状态未变且无可执行问题时不重复催促。

## 4. 保留旧结果，复测整题

旧题包、旧rubric与原成绩保留；修改理由、影响范围及新版本另记。若纠正旧答卷评分，区分同标准纠错与新标准探索性复判，不覆盖首次成绩，不把它们叫新运行。新版本同步检查输入、标答与考点；是否投入真实复测统一按[研发决策](difficulty-design.md)。需要验证新版难度时按预定条件独立运行，未测则标未测，不能迁移旧分数，也不因一次评分纠错自动再调用模型。[S006 I03；版本管理为本库约定]

保留历史正确解是留存证据，并不要求重新设计的业务任务保留全部旧结构。变更委托和依赖时重新核验可解性及合理替代解；旧解在旧输入下的有效性不变，在新输入下是否适用则另行判断。

返修先区分实际模型失误、材料歧义、缺条件、提示泄漏和评分问题；依据原因修事实、字段、参考或规则，不能为了防止模型再次出错，把对应解题步骤填回公开输入。表述修改保留原事实，业务条件变动同步输入、标答与评分并另存版本。

集中返修后按[模型可见材料的整包复审](design-review.md#模型可见材料的整包复审)通读当前题面、实际提示词及全部附件，检查所有工作表及其他可见内容，先找齐同类问题再按文件修正。除改过的句子外，还须回查同一判断是否仍从另一摘要、字段、表头、全局保证或操作说明提前给出；不能用删掉上次指出的句子证明关系已留给作答者。

消歧若新增顺序、适用分类或方案边界，立即更新同一份“核心判断归属”记录中的已给工作、剩余判断、能力声明及私有验收依据；质量修复成功不等于原难点仍存在。保留外生制度、单位、权限、时点和必要数据，检查正常分支、合法替代解以及删改后是否仍能从公开原件独立推导。最后回读保存原件，复算受影响标答，在现有业务审查报告中引用当前记录与 `input_digest`；未关闭的责任归属冲突或缺条件问题不得记为 `passed` 或直接进入下一正式投测。私有审计表及原因分析不回填公开材料。历史缺证另作复核记录，不伪补旧版事前审查，也不追改旧答卷和原成绩。该方法不要求一律等两份答卷，也不新增测试次数。[S011 L24、L26、L30–33、L71；S015第3–4、7–8条；采用完整复审原则，不猜补L24残句]

S010第5节原话“不追判旧答卷”未区分同一冻结标准下的评分纠错与换标准复判；第6节又要求争议回到同答卷、同标准及证据位置。本库保留这种歧义，继续分列原评分、同标准纠错及新标准探索性复判，后者不作为原始正式成绩或新题包运行，不把该来源静默改写为任意追溯扣分许可。

复测查看整份交付物、当前版本全部验收责任和正确反例，防止局部修复遗漏关联影响。对仍可比较的责任，分析同配置下稳定正确、稳定错误及波动的位置，保留所有运行；跨题包、rubric或模型版本不直接比较总分。无需固定三次，更不能只保留最低分。正式通过仍须官方反馈，不能由本地低分或前置检测状态代替。[S007 E18、E20、E27]

## 5. 保存实际成功与失败路径

在对应 `tasks/<task-id>/` 的记录中保存：触发条件与输入版本、错误产物位置、业务影响、考点及评分版本、根因与不确定性、正确反例/成功运行、修订和复测结果。没有反例或复测就明确写未取得；单次现象标单次观察，跨案例支持后再提炼为稳定模式。[S007 E19；条目字段为本地约定]

正确运行也进入同一经验记录：保存实际方法、哪些阶段共享同一计算或状态重建、适用输入与规模、未覆盖责任，以及对下一候选优先级的影响。可复用的是有范围的成功或失败证据，不能把某类算法、行业或可编程任务全面排除。一个公共处理结果支撑多份交付，可能使多阶段任务被同一方法覆盖，应扣除重复计算的难度主张；它也不证明所有完整链条都容易。组合机制仍核业务依赖及可解性，不迁移旧分数，不把测试夹具写成真实成绩。

经验记录复用稳定 `EXP-` ID，至少说明触发条件、输入／评分／运行引用、观察事实、原因假设、实际做法、正反例、证据限制及最近实际验证日期。状态可用“待核实／本案例支持／跨案例支持／有反例／已失效”，独立于用户是否采用某项偏好。出现反例后缩小适用范围或标记退役，保留旧依据与替代入口。同一次运行的重复叙述不增加验证次数，检索日期不充当验证日期，无实质新证据不刷新。统一入口见[题目工作记录](../templates/task-record.md)。
