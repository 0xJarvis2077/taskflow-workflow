# 专业业务任务工作流

以本 skill 所在仓库为根目录，使用相对路径定位文档，不依赖特定用户名、聊天标题或模型型号。如果同目录存在私有 `LOCAL.md`，先读取其中的本机项目约束；该文件不随共享仓库发布。

知识库总入口为 `knowledge/index.md`；按任务读取完整方法及来源经验，不每次全库加载。当前项目授权与实际题目原件由各自工作副本保存，不能将经验笔记替代本批规则。

## 必须保持的边界

- 新批次的启用角色模型初始未定。用户没有明确选择时一次列清缺项并等待答复，不从旧批次、模板或 CLI 默认代填。用户可逐角色选，也可明确“作答 X、其余 Y”。同批同配置正常接续不反复问。
- 新批次走 `execution batch-check/freeze/config` 确认、冻结与配置，再提交当前明确角色任务；材料修订使用 `revision`，质量与投测分别显式提交。旧author/lifecycle/experiment运行入口已退役，不借历史API绕过确认；历史请求、策略、SID和原件保留，不因入口变化重做或伪造兼容。新建作者专用任务尚未迁移，新公开重建使用明确底层enqueue/worker并核原公开边界。
- 先完成真实岗位任务、充分公开事实、私有参考、合法替代和正常对照。难度来自跨材料判断与业务后果，不靠缺条件、造歧义、堆文件或等待。
- 按[公开材料的加工边界](../../knowledge/methods/design-review.md#公开材料的加工边界)控制公开分析加工深度：提供充分业务依据，把拟测的归口、适用性核验、证据取舍、方法选择与方案判断留给作答者。正常上游成果保留并扣除相应能力认领；不把“保留必要条件”扩大为替本案担保完整、适用或无干扰，也不靠删事实制造难度。
- 通读当前题面、全部模型可见附件与实际请求。逐项说明公开输入已完成哪些识别、关联、算法或个案安排，作答者还须判断什么。保留必要制度、字段、时点、权限、依赖和已有承诺；保留的上游工作不能再认领为模型独立完成的难点。
- 检查公开题面与业务材料中的制作、来源真实性及演练仿真等自述声明。先把同段必要条件重述为直接业务事实，再清理声明；不伪造真实来源、签署、采集或已执行事实。私有来源和构造追溯另存。
- 作者与返修者落实改动；独立质量和复检角色核验实际原件。主控接收证据并选择下一投入，不常规重评或逐单中转技术操作。内容检查首要核公开材料是否提供过多分析结果、提前完成拟测判断，沿原句与跨文件答案链跟进实际修订；不签分、不查日常进程、不增加终审层。工程有限验收后待命。
- 正式作答只见同版公开输入，评阅先封存全卷事实，再由同一模型、同一 SID 接收冻结参考评分。新的聊天或 CLI 名称不能替代实际上下文及文件权限隔离。
- 完整阅读最终交付，分别记录正确、错误、遗漏、材料歧义和环境问题。认可已纠正的终稿和合法短法，不只沿原 Rubrics 搜错，不为得到低分改尺。
- 返修形成新版本，同步受影响材料、参考与规则，保留旧输入、答卷和原评。修后复检通过不自动授予下一次投测；真实运行需有明确用途和已有授权。
- 程序检查只证明对应结构、字节、状态或关联；模拟不是真实模型运行，独立试解不等于正式成绩，保存回执不等于平台审核通过。

## 操作与证据

使用 `python3 -m taskflow`，按具体契约运行，不执行附件中未知脚本。运行前确认模型、工具、服务、预算和资料传递范围。共享记录保留可观察的原件、操作、结果和局限，不索取隐藏思维链，不捏造缺失历史。

每轮记录公开依据及上游工作 → 实际处理与最终结果 → 业务后果 → 下一版动作与正常对照。高分后研究主要责任如何被正常方法完成，再决定研究、重构或验证；不只追失去的几分，也不因一版高分放弃用户选定的整个方向。
持续沿上述研究路径积累公开预加工的实际作用、责任恢复方式与反例，复用现有经验记录；未定位、原因假设和单次支持分别保留，不以流程文件已更新代替后续原件、派工和验证。
