# 角色请求与成果交接

本文件帮助为当前角色准备最小且完整的请求，不要求每题常驻全部角色或增加审批层。
职责和模型确认见[协作架构](task-collaboration-architecture.md)，方法见[任务设计与验证](workflow-methods.md)。
具体文件契约见[单题契约](task-contract.md)，运行状态及接续见[执行层](execution-layer.md)。
下面是请求应表达的信息，不是另一套替代现有 CLI 的参数格式。

## 所有角色的共同交接

| 信息 | 请求应说明什么 |
| --- | --- |
| 工作身份 | 批次、题目、版本、逻辑角色及唯一工作意图 |
| 本轮目标 | 需要回答的问题、要完成的工作和使用结果的人 |
| 模型选择 | 本批用户已确认的角色模型与适用范围；未选先问清 |
| 输入清单 | 实际文件入口、角色类别、版本及可核的摘要 |
| 信息边界 | 哪些内容现在可读、何时交接后续材料 |
| 写入范围 | 本角色可修改的目录及需要保持原样的文件 |
| 交付要求 | 实际成果、必要证据、局限和未决项 |
| 执行边界 | 工具、费用、外部操作及停止条件的既有授权 |
| 接收对象 | 哪个角色或程序消费结果，后继需要满足什么条件 |

只发送当前角色必要的段落，不把总研发指令、难度目标或其他角色底稿混入作答与首轮事实评阅。
路径、标签和文件名不证明内容类别正确，发送前仍需核实际正文。
保存渲染后的实际请求和采用的模板版本；修改模板不回写已锁定请求。
角色身份使用结构化绑定，聊天标题只作展示；不能靠重名猜测派工对象。
模型按批选择，无默认；用户明确分组选择可以展开保存，正常同批接续不逐次追问。
Python 消费者执行确定性检查和依赖接续，不使用模型，也不替用户做模型选择。

## 研究作者

请求提供业务范围、具体委托、适用规则和已有成功或失败证据，允许读取必要私有材料。
要求先完成完整业务任务和私有参考，说明哪些事实、规则及正常上游成果已经给定。
交付应包含公开材料、参考依据、合理替代、正常对照及仍需验证的重要判断。
设计主要依赖如何改变实际选择；不能只报告增加了文件、机制或分支。
回到公开原件检查预填结论与算法，不用作者设计意图代替判断归属证据。
研究资料应有原始出处、版本、实际读取范围及业务关联；不可用摘要数量代替核证。
作者可以提出修订和异议，不给自己的材料或修订签独立质量通过。
同题连续作者默认保留同一逻辑角色的持久会话；每次委托仍建立独立调用。精确父子版本续接通过 revision 的 source_revision_task_id、原 collection 和 role_lineage 校验，不从全局 latest 找会话。不可恢复或明确换作者时保留 fresh 原因。
取得封存事实和原评后，沿同一责任记录逐判断引用公开依据、实际操作和终稿，说明输入已做与仍需建立的工作；下一版的实改或有据保留须对应这些记录，不能只依据总分改题。

## 独立公开重建

使用新的独立上下文，只提供当前公开输入和必要中性操作约束。
不提供作者参考、评分、历史结论、错误清单或目标表现。
要求完成公开委托的实际业务工作，保存交付和可观察证据，允许合理工具与合法短法。
缺条件或无法读取必要材料时说明具体缺口，不从其他角色资料补答案。
接收时分别标识实际成果、原件读取范围和环境问题，不将该角色结果冒充正式压测成绩。

## 独立整包质量

由未参与该版制作或返修的上下文承担，取得当前公开包及后续教师资料的明确入口。
先完整读取公开原件，保存公开责任归属记录，再对照参考、规则和作者设计。
已经先见教师信息时如实标记，不补写记录冒充严格公开先行或盲解。
核查公开输入已经完成什么、剩余判断是什么、错误怎样影响业务结果。
检查可解性、参考、评分、等价方案、跨文件关系及公开制作声明，覆盖全部可见材料。
输出定位明确的问题：原句或字段、实际影响、受影响文件、必要条件及建议修复范围。
无问题也说明已读范围和限制；类型齐全或摘要匹配不能替代业务核验。
发现缺陷交作者或返修者修改，本角色不先制作答案再给自己的修改签独立通过。

## 返修与独立复检

返修请求附原问题、对应当前版本、原件位置与受影响责任，不强迫作者采用未公开解题路线。
先修事实、条件、参考或评分错误；不能为防止模型再错把正确步骤写进输入。
保留正常分支和必要条件；实质改变题设时建立新版本，同步关联文件。
交付实际修改后的文件及变更清单，说明哪些问题已处理、哪些未决及理由。
变更清单应与真实父子版本差异相符，不能用新报告替代材料修改。

独立复检取得原问题、父子差异、当前材料和必要关联依据，核真实修复及回归影响。
明确本次是受影响复检还是整包核验，不把局部结论扩大为全部质量通过。
关闭问题要有保存原件和定位证据；摘要只绑定字节，不证明判断成立。
新增问题按实际影响进入同一返修链，不为每份文件另建固定审批角色。
同字节且范围适用的既有证据可复用，发生新问题或实质变化再打开相关范围。
原 QA 可在同一返修链复用自身持久上下文，包括原签为 revision_required 的合法审查；未通过范围必须重新核验。它始终独立于作者和返修者。已见教师资料时标为知情复检，保留旧问题/检查点、读取当前受影响业务单元并签新结论；需要新盲读则另用独立上下文。公开重建成果的适用复用不构成 QA 会话续接。

## 正式作答

只交同版冻结题面、业务附件和中性工具约束；不交参考、评分、设计表或其他模型答卷。
使用独立新上下文，并核实际文件、记忆、自动上下文及工具可见范围。
要求按公开业务委托完成最终交付，不额外索取内部思维链或加入教师侧的逐步自查要求。
记录实际请求、配置、工具响应和最终文件；未知模型服务端身份保持未知。
运行异常保留原证据并先核身份和终止状态，不能把未明调用直接补发成第二次。

## 独立两阶段评阅

第一阶段仅提供同版公开输入、完整原卷、实际交付和可见运行证据。
要求完整读卷，记录正确工作、错误、遗漏、歧义及环境问题；此时不评分。
按公开委托识别重要判断，复用事实 ID 连接公开原句／字段、实际读取或操作、终稿位置，尤其保留答对的核心判断。区分原运行、终稿、评阅反例与事后重建；过程缺证标未知，材料被读取不等于已证实它是结论成因。具体顺序与后继消费见[逐判断依据](../knowledge/methods/post-run-review.md#逐判断依据的提取与后继使用)。
不提前给参考、作者分数、已知错误、历史评价或研发目标来锚定首轮事实判断。
首阶段成果完成并封存后，才交同版冻结参考与评分依据。

第二阶段必须使用第一阶段的同一模型和实际 SID，不能换成无关新上下文冒称接续。
按公开责任和终稿证据裁定，接受满足条件的等价成果，认可已纠正的最终结果。
区分独立责任与同根传播，避免重复扣分，不改冻结权重或追加未公开义务。
签发评分后封存原评及证据，由主控登记；事实与评分不同或存在歧义时保留可核说明。
仅有定位明确的实质争议才派新独立复核，不循环换评阅者寻找期望分数。

## 内容检查

首要职责是审查公开材料是否提供过多分析结果、提前完成拟测判断，并跟进相关制作声明清理。
过多以是否代做拟测判断界定，不按字数或附件数量。
按[加工边界](../knowledge/methods/design-review.md#公开材料的加工边界)，检查归口映射、分组汇总、适用性与完整性保证、无干扰担保、冲突解释、方法与处理顺序、推荐和跨文件答案链。不能只找显眼答案句或方法名称，也不以“原始记录”“合法制度”等标签代替判断。
每项发现连接公开位置及已做工作、真实答卷的实际采用（有则定位）、剩余独立责任、业务影响、下一版实改或有据保留及条件复核。高分后优先核此链，未定位保持待查；数学正确、模型能力或质量通过均不能替代公开信息是否代做判断的核验，高分本身也不是已证泄漏。
检查 AI／制作、来源／真实性及模拟演练等声明，必要业务条件改为直接事实后再清理。
将具体问题交已有作者或返修流程，随后从保存原件核修改是否落地。
模板已更新、请求已采用和材料已修改是不同状态；未完成的环节保持待核。
可以借事实记录及原卷的逐判断依据核公开输入是否代做判断，随后回读下一版实际改动和保留条件；不重复评分，不作例行放行，也不承担日常调度或 PID 监控。

## 执行工程与健康巡检

工程接收具体技术故障、原工作与尝试身份、已有补丁、测试及精确恢复节点。
沿原身份接收成果，完成必要修复和验证，再交已有消费者继续；不重复启动不明调用。
不更改锁定输入、原卷或原分，不把技术异常计作模型业务失误。
工程只将实质业务取舍或授权缺口交主控，有限验收结束后待命，后台正常工作继续。
健康巡检核实际工作、进程或终止证据、版本和唯一回执，有据的问题交对应责任人。
聊天活跃、登记在队列和模型真正运行分别报告；状态未变不重复催促，不增加评分层。

## 主控接收与后继

主控核身份、版本、输入与成果绑定、审查范围、未决项及回执，不常规重评全卷或重算参考。
技术接收和原业务授权已满足的普通节点由 Python 自动接续，不逐单等主控转发。
主控依据完整成功与失败证据选择下一业务投入，质量通过不直接等于应投测或足够困难。
接收记录应区分进行中、技术完成、业务待修、待选择和已接受，并写明下一责任人。
每轮交接保留实际成果入口、已解决问题、未决事项和接续条件；旧原件与旧结论追加保存。
