# GitHub 分享与持续同步

同步工具只发布通用工作流、Python 代码、测试、文档、skill 和可复用知识。具体题包、附件、答案、真实答卷、成绩、运行库、原始来源和本机配置留在本地。

## 配置与首次使用

需要 Python 3.10+、Git、已登录且有目标仓库写权限的 GitHub CLI（`gh`），以及支持 `fcntl` 的 macOS 或 Linux。先由仓库所有者明确授权公开范围、目标仓库和后续同步；工具不会自行创建仓库或推断账号。

复制 [空配置示例](../config/examples/github-sync.example.json) 为 `config/github-sync.local.json`，填入源目录、私有镜像目录、仓库、分支、私有状态文件和提交身份。推荐使用 GitHub 的 noreply 邮箱。镜像应是专门用于同步的空目录，不能是工作库、题目目录或另一份有人编辑的 checkout。

```sh
python3 -m tools.github_sync --config config/github-sync.local.json
python3 -m tools.github_sync --config config/github-sync.local.json --push
```

第一条只检查本地候选并预览，不调用网络、运行测试或提交。第二条检查镜像和远端状态，在独立快照中执行完整离线测试，通过后提交并进行普通推送，再核对远端分支 SHA。它们不读取或修改正在研发的项目执行数据库，也不启动真实模型；离线测试只使用中性临时夹具。临时快照与日志不进入公开仓库。

工具使用根目录 `.gitignore` 枚举候选，并额外执行固定目录白名单、文本与大小检查、已知敏感模式扫描、Python/JSON 语法及 Markdown 本地链接检查。修改忽略规则使私人目录被选入会阻止发布；不能靠扩大 `.gitignore` 范围绕过代码边界。模式扫描只能发现已知形态，发布前仍要人工确认新增内容属于可复用方法，没有题目细节或私人信息。

## 日常迭代

只有在用户授权持续发布且本机配置存在时，才在完成改动审查与相关验证后运行同一 `--push` 入口。可另设每小时一次的补漏检查；没有变更时不重复跑完整测试。共享仓库的使用者需要自行授权、配置和启用定时任务，这些设置不随本仓库传播。

每次使用保存的目标配置，不自动换仓库、账号或分支。源库的实际工作继续在原目录；镜像只保存公开文件，不在含有私人材料的工作根目录执行 `git add --all`。后台同步与交互同步使用同一个文件锁。

成功需有 `pushed` 或 `pushed_pending_commit` 回执及匹配的远端 SHA；`preview`、本地 commit、发送命令和定时任务已启动都不算远端同步完成。`no_changes` 表示已验证记录对应的公开内容没有变化。

## 失败与恢复

- 测试失败、公开源文件在验证期间变化、敏感内容命中或候选超出边界：阻止提交，修复并重新验证，不跳过检查。
- 镜像有任何未提交文件（含被忽略文件）、目标不符或远端领先／分叉：停止并保留现场，由维护者核实；不自动 reset、覆盖或强推。
- 已提交但推送失败：保留原 commit 和验证记录，下次优先重试同一 commit，不重复提交。若源库已有更新，旧 commit 恢复后还需下一次同步发布新内容。
- 若进程在 commit 已写入、待推送记录尚未落盘的短窗口退出，下次会因本地与远端不一致而停止，需要维护者核实该 commit 和验证记录后恢复，不会猜测并强推。
- 同步进程已持锁：本次退出，保留另一轮工作。不要为了重试终止题目研发或其他在途任务。

状态、锁、测试日志和镜像均为本地运行记录；不能把它们纳入下一轮提交。发布工具的成功只证明该快照通过了所述检查，不代表题目难度、模型隔离或平台质检通过。
