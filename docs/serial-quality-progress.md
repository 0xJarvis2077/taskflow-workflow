# Serial quality progress compatibility

Structured page evidence supplements the legacy path/location format without replacing its original bytes. The page keeps its exact assigned ID, hash, disposition, substantive association and remaining responsibility. A structured receipt requires one plan_page matching the assigned locked page; a queue_record exact line in a locked dependency whose page ID/hash/size/name/source_refs match; every assigned original source ref in resolved_original_sources; and queue/hash tool-output IDs found only in the original owned custom-tool output records. Model commands, prose echoes and nested JSON inside tool output strings cannot supply IDs. Read claims must retain their explicit body-read location. Same-byte claims additionally need the actual full-body tool-output ID in the sealed prior same-SID prefix. Optional supplementary observations stay raw and do not establish coverage by themselves.

A repeated later public checkpoint is accepted only as an exact object-equal reference to the sealed first progress checkpoint; the first original/collection and actual public SHA readback are revalidated. It never replaces that seal or establishes a new blind read.

These checks validate transport, locked source identities and observable locators. They do not certify the truth of every semantic source statement, comprehension, whole quality, business acceptance or credential isolation. Remaining duties and the final independent whole judgment stay unchanged. No artifact/request/old seal is rewritten and no path/location or readback is fabricated.

A second explicit split legacy representation separates body_page/bytes/body-output locator from queue/source bindings. The parser binds its exact assigned page, queue line, turn and source refs. Standard owned output IDs are locators; orchestrated PAGE-header fallback additionally requires the full locked page body in the owned response and a successful bound command output. Neither format certifies comprehension. Unknown or ambiguous shapes remain rejected.

Future unprepared read-turn requests explicitly require every evidence item to contain nonempty path and location strings, give a neutral schema example, and require local structural checking before delivery. Optional rich observations remain additional fields; later public_checkpoint must be null. Existing prepared requests, original reports and old seals are not rewritten.

Legacy page.remaining may be a string or a list of nonempty duty strings. The original value is retained without flattening or resolving duties. An empty list contains no duty; unresolved pages still require a nonempty string or nonempty list. Numeric, boolean, nested or blank list members reject. Future unprepared requests prescribe page.remaining as a string and explicitly distinguish it from top-level facts/remaining arrays; the full six-field page schema and placeholder example are rendered before delivery.
