# 专业任务设计与验证方法

本方法用于设计需要专业判断和实际交付的业务任务，也用于审查材料、参考答案与模型表现。
它提供研发判断方法，不承诺某类题目必然困难，也不代替交付项目的具体规则。
角色与模型设置见[协作架构](task-collaboration-architecture.md)，派工见[角色交接](role-handoffs.md)。
文件契约见[单题契约](task-contract.md)，运行与自动接续见[执行层](execution-layer.md)。

## 先确定本批任务边界

明确行业、交付对象、题目范围、可用工具、费用与调用边界，以及本批的完成条件。
平台、客户或组织要求应记录版本和适用范围，不将过往要求自动变成当前约束。
各启用角色的模型由用户选择；未选齐时集中询问，不从旧配置或模型能力印象补值。
同批同配置的正常迭代不重复询问；新增角色或改变已确认配置时只补问相关部分。
批量设计时，以核心决策、证据关系和验收责任去重，不能仅凭标题或材料不同认定题目不同。

## 从岗位工作确定任务

先说明谁需要结果、要作出什么决定，以及错误会造成什么可观察的业务后果。
研究应找到可核查的机制、记录和规则，而不只是收集行业术语或泛泛的常见错误。
对承载关键判断的资料回读原文，记录适用主体、形成时间、效力范围和未取得的部分。
引用事实、题设数据与设计假设分别留在私有底稿；不能把设计记录虚称为已发生事件。

将完整任务连接成有依赖的业务工作：

- 哪些事实由输入提供，哪些属于正常上游成果；
- 接手者还需识别、关联、核算或权衡什么；
- 这些结果共同改变哪个决定，而非各自完成互不相关的小问；
- 决定如何落到可执行的交付、资源安排或后续责任；
- 哪些替代、拒绝或延期方案在给定条件下同样成立。

先完成完整业务设计、私有参考和正常对照，再判断哪些内容值得验证。
不把一个局部关系尚未出错作为扩包前提，也不因总体目标未达而自动制作下一完整包。

## 让材料提供依据，保留作答责任

题面交代角色、目标、范围、时点、交付物和必要验收要求。
附件按实际岗位和文种提供记录；形成时点与当时可掌握的信息应一致。
公开材料按[加工边界](../knowledge/methods/design-review.md#公开材料的加工边界)提供充分业务依据，分析加工深度以作答责任为界。私有参考保持完整，公开材料把拟测的归口、适用性核验、证据取舍和方案判断留给接手者；收回预加工结论时补足可核原件，不靠删条件或打乱材料增难。
不能把待推导的推荐、诊断、选择或执行安排提前写成附件结论。
同事口吻、表格形式或系统导出样式不能改变一段内容已在代做判断的事实。

同时保留完成工作所需的条件：

- 对象标识、字段含义、数据、单位和期间；
- 合法制度公式、权限、期限及适用边界；
- 状态、生效与撤销关系、依赖及已有承诺；
- 支撑正常路线和合法替代方案的必要事实。

否定词、期限提醒或明确流程不应被机械删除；先核它们是否承担必要业务含义。
未知、未收到或空值不能擅自改成未发生、失败或已否定。
消歧优先解释事实和字段，不能借消歧把正确处理步骤补进公开输入。

## 逐项检查公开材料是否提前完成判断

在初稿后、投测前、返修后和交付前，通读实际题面、请求及全部模型可见材料。
表格需覆盖全部工作表、可见内容和注释；其他格式按实际可取得内容检查。
发现一处问题后查齐同类问题，再按文件集中修改，不能只搜关键词或复查上一轮改句。

每个主要责任应能回答以下问题：

| 核查项 | 要记录的证据 |
| --- | --- |
| 公开位置 | 原句、字段、单元格或跨文件组合及当前版本 |
| 输入已做的工作 | 已给的归口、映射、筛选、算法、中间结论或本案安排 |
| 剩余责任 | 作答者还必须建立的关系、判断与可用路径 |
| 业务影响 | 该判断怎样改变决定、执行或交付结果 |
| 处置与复检 | 保留、修订或缩小能力声明，以及必要条件仍充分的依据 |

重点检查完整性保证、已清洗分组、冲突解释、定向防错、预填模板及多个片段拼成的答案链。
合法规则和正常上游成果可以保留，但它们已经完成的工作不能再计作独立判断能力。
需要恢复待测责任时补足可推导的原始依据，不能只删答案式句子，留下缺条件的任务。
文件隔离、哈希一致或计算正确，均不能代替这项语义审查。

## 清理公开材料中的制作声明

检查题面、附件、说明、拟交付文档及可读属性中的制作方式或来源身份自述。
清理 AI／模型制作、来源／真实性自述，以及模拟、演练、仿真等同类声明，不换成隐晦同义说法。
检查范围包括文件名、正文、页眉页脚、全部工作表、注释和可读属性。
声明同段若含必要数据、状态、范围或验收条件，先重述为直接业务事实，再清除声明。
必要时重构材料；不能因清理制造缺条件，也不能新增真实采集、签署或生产执行的无据主张。
来源、设计范围和验证过程保存在私有追溯中，不混入作答材料。
这项清理不自动代表题目变难，也不单独构成重新调用模型的理由。

## 独立重建参考与评分依据

从作答者实际可取得的输入重建参考，核单位、时点、状态及跨文件勾稽关系。
保存计算或推导依据，并用正常路线、边界及有业务后果的错法检查结果。
参考不是唯一表达形式：符合公开条件的替代解法、跨表表达或压缩交付应可验收。
若还需评阅人补政策、归属、授权或业务选择，不能把补做后的结果当作已经交付。
评分围绕公开要求和可观察成果，按可判定的责任制定；不用作者偏好的步骤或表头代替业务要求。
区分同根错误的传播和不同责任的独立缺陷，避免重复扣分。
参考或材料仍有歧义时先修质量，不把无法可靠判分当成有效难度。

## 冻结后再执行真实验证

冻结同版题面、附件、参考和评分依据，记录实际版本与配置。
作答者只取得公开输入；新上下文本身不证明文件和自动上下文已经隔离。
保留实际请求、工具响应、最终文件、运行轨迹及异常，确认必要原件确被读取。
不在运行中修改锁定输入，不把环境失败当成业务失误，也不为留证重复抽同一道题。
独立公开重建、作者试解、程序测试与正式模型运行分别标识，不能互相冒充。
质量通过说明对应质量范围成立，不能据此预告模型低分或自动判定难度达标。

## 先完整读卷，再评分与归因

读完整最终答卷和交付文件，先记录正确、错误、遗漏、歧义及环境问题，再对照冻结规则。
认可模型已经纠正的终稿结果，不用初稿错误代替最终表现。
评阅首阶段保存全卷事实并封存；随后由同一模型、同一实际 SID 接收参考与规则评分。
主要成功也进入复盘：记录实际方法、覆盖范围和上游已完成工作，不能只追失分的小项。
高分是需要解释的观察，不自动证明泄漏；低分也必须经过材料、参考与有效性核验。

## 用证据驱动下一轮

将“公开依据 → 实际处理 → 最终成果 → 业务后果 → 下一动作”对应到原件位置。
先区分模型失误、预解题、歧义、条件不足、评分问题和运行故障，再交对应角色处理。
材料有误则形成新版本，同步受影响附件、参考与评分；旧答卷和旧分保持原记录。
实质增难应恢复或引入会改变主体选择的证据关系，不靠堆文件、重复分支或人为等待。
用完整成功方法检验新设计是否仍被覆盖；允许正常短解，不为阻止短解追加无业务依据的限制。
当前候选不值得继续时，保留方向与可复用材料，再确定下一项具体业务投入或真实阻塞。
修复后复检改动及必要关联；方法或模板更新还须核下一实际请求和产物是否采用。
完成已授权的一轮后自动接续正常后继；仅实质业务取舍、授权缺口或明确停止条件交回主控。
最终从保存原件回读题包、参考、评分与交付清单，分别报告质量、实测表现和交付状态。
